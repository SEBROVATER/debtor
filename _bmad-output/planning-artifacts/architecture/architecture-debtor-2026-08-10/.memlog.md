- (question) Choose the named paradigm: recommended Hexagonal Architecture with a domain-centric layered core, versus Clean Architecture or plain Layered Architecture.
- (decision) Adopt Hexagonal Architecture with a domain-centric layered core. Binds all production crates and prevents adapter wiring or framework concerns from bypassing application-owned ports. Map domain to debtor-domain, use cases and ports to debtor-application, driving HTTP adapter to debtor-web, driven adapters to debtor-infra, and composition to root.
- (question) Choose participant-archival concurrency coordination: recommended process-local mutation epoch with snapshot/revalidation, versus holding the global write gate across rate I/O; persistence-owned recalculation is rejected by the chosen boundaries.
- (decision) Use a process-local ledger mutation epoch for participant archival. Binds participant lifecycle, debt snapshot reads, and every ledger mutation; prevents archival from committing against a balance snapshot invalidated during rate I/O. Capture snapshot plus epoch under the write gate, release the gate and database transaction before provider I/O, then reacquire and archive only if unchanged; mismatch is retryable with no state change, and no database revision column is introduced.
- (question) Choose shared-state ownership for the mutation epoch: recommended SqliteLedgerRuntime co-owns gate and epoch, versus a root-owned decorator or participant-specific epoch.
- (decision) SqliteLedgerRuntime owns both the universal ledger write gate and mutation epoch, and root composes exactly one runtime per process. Binds all repository adapters and prevents split serialization or stale archival validation caused by per-feature coordinators.

- (constraint) Root to web/infra to application to domain is the only permitted dependency direction; web and infra may use domain values through application-facing contracts, and only root composes concrete adapters and owns lifecycle.
- (constraint) Application owns transport-neutral commands, use-case orchestration, lifecycle and allocation policy, clocks, and narrow ports; domain owns synchronous deterministic rules; infra owns external adapters and authoritative transactional race guards; web owns HTTP, forms, sessions, CSRF, rendering, safe error mapping, and harmless read composition.
- (constraint) Group owns participant accounting identities and spending history: one participant belongs to exactly one group, identities are never reused across groups, referenced identities are archived rather than deleted, and historical allocations remain readable.
- (constraint) Rust owns all monetary truth using exact Decimal, canonical TEXT persistence, minor-unit validation, checked deterministic arithmetic, and Rust aggregation; floating point and SQL monetary arithmetic or aggregation are forbidden.
- (constraint) Every ledger mutation uses the one process-local write gate; aggregate eligibility checks and writes are transactionally authoritative in infra, while application prechecks provide policy and feedback. Admitted valid operations use last-committed-write-wins without database revision columns.
- (constraint) Complete aggregates are loaded from one SQLite snapshot and database transactions end before provider I/O; rate-dependent calculations use injected application ports and deterministic domain rules.
- (constraint) Root composes one instance per process of each shared state owner: SQLite runtime/gate/epoch, session store, login limiter, rate caches/single-flight/provider semaphore, request permits, and supervisor health. Per-request or per-feature reconstruction is forbidden.
- (constraint) Every unsafe route uses the shared authentication and CSRF boundary plus a bounded expiring session-bound single-use submission token reserved immediately before dispatch. Generic timeout ends at mutation dispatch; after dispatch the response must report definitive commit or rollback.
- (constraint) The supported production topology is one application process, one local WAL SQLite volume, and one sanitizing HTTPS reverse proxy; TLS, HTTP/2/3, early-data rejection, forwarding sanitation, and certificates stay at the edge. Multiple app instances, external SQLite writers, and persistent sessions are unsupported.
- (constraint) Outer diagnostics map to structured safe application reasons and sanitized HTTP responses; secrets and request-derived sensitive values never enter logs. Probe readiness covers SQLite and mandatory in-process supervisors, never the rate provider or ledger contents.
- (direction) Defer concrete schema/table shape, route/template layout, obsolete-scaffold migration sequence, reverse-proxy vendor, deployment automation, telemetry backend, and future horizontal-scaling design; fixed ownership, edge contract, and first-release topology are sufficient for convergent epics.
- (constraint) Permanent product boundary: one administrator password gate only; no username, registration, user or tenant model, participant authentication, or multi-user authorization. Participants are accounting identities.
- (constraint) Spending policy permits exactly one payer for the full total and only Proportional positive-weight or Exact shares; largest fractional remainder with participant-ID ties constructs proportional allocations. Multiple-payer and Equal-mode APIs are superseded.
- (constraint) Archived groups are read-only. Spending updates may retain an archived participant only in the same existing payer or share role and may not introduce or change that role.
- (constraint) Monthly summaries retain source-currency totals when rates are unavailable and mark only converted totals retryably unavailable; debts and archival calculations remain all-or-nothing.
- (constraint) Residual allocation and final balance quantization use largest fractional remainder with participant-ID ties; settlement uses descending absolute balance then participant-ID deterministic greedy matching.

- (constraint) Operational budgets, session and login-limiter admission semantics, provider limits, startup ordering, shutdown behavior, edge body limits, and mutation-compatible proxy timeouts are shared architecture invariants exactly as fixed in specs/design.md and accepted ADRs, not per-feature choices.

- (decision) Submission tokens use one web-owned process-local store with separate pools: anonymous capacity 4,096, maximum one per session, ten-minute inactivity expiry; authenticated capacity 1,024, maximum 32 per session, 30-minute absolute expiry. Capacity fails closed with retryable feedback, cleanup is indexed, and reservation becomes terminal after exactly one dispatch regardless of outcome or response delivery. Binds all unsafe forms and prevents anonymous starvation or per-feature stores.
- (decision) Accept time-of-decision exchange-rate truth for participant archival. One attempt binds an immutable ledger snapshot, calculation context, and quote bundle; final admission revalidates ledger epoch, UTC date, and quote eligibility. Rates and archival quote evidence are not persisted, so a later attempt may observe a provider revision. Prevents mixed-context commits without adding derived durable state.
- (decision) Proportional weights are positive decimals at most 1,000,000 with at most six fractional digits. Normalize one submission to integer ratios at its maximum scale; use checked i128 total-minor-units times weight, quotient/remainder by total weight, descending remainder and ascending participant-ID residual assignment. Preview and commit share one operation; invalid or unrepresentable input is Validation with no aggregate. Binds spending/application/domain and prevents finite-Decimal evaluation divergence.
- (decision) Converted monthly summaries accumulate each spending exactly, then quantize final per-payer totals together to target minor units using truncation toward zero, descending fractional remainder, and ascending participant-ID ties; displayed group total is their exact sum. No per-spending rounding feeds aggregation. Any checked conversion/aggregation/quantization failure leaves source totals available and makes the entire converted section unavailable under one sanitized calculation reason.
- (decision) Definitive dispatched mutations outrank a fixed total shutdown deadline. Ten seconds bounds HTTP connection draining only; root then waits for the dispatched-mutation registry to reach terminal commit/rollback states before WAL checkpoint and pool close. Individual waits and I/O remain bounded, but total shutdown duration is not fixed. Prevents ambiguous committed outcomes without persistent idempotency state.
- (constraint) Rate key model: for original request R and calculation date C, fetch date F=min(R,C); dedupe/single-flight/cache key is source,target,R,F, provider effective date is returned evidence. Fixed past uses exact stale match; current uses latest prior current-class; future also matches original R; refreshable fallback is inclusive through prior F plus seven UTC days. Same-currency is synthetic exact one without provider I/O.
